# Quiet installer feedback — proposals for Raneem

Reviewed 8 November after handing a customer plan to `#/installer` in the browser and viewing the desktop design studio. These are proposals only: Raneem picks what to build. The separately requested safety vest is not approval to implement these ideas.

The current studio already auto-applies edits, reports pricing status, and shares module arrival animations with the customer scene. Keep that flow and the current layout. S = small local UI change; M = coordinated state/scene change with a focused regression check.

| Idea / what changes | Why it helps a planner | Files | Effort |
|---|---|---|---|
| **One quiet re-derive highlight.** Briefly tint only changed total/summary values when a successful response arrives; keep the existing before → after banner. Retrigger on a new response, never animate or count through intermediate numbers. | Shows where to look after an edit without making the planner reread the whole plan. | `src/Installer.tsx`, `src/installer.css` | S |
| **Shorter module landings in the studio.** Add an optional planner motion mode to the existing landing animation: newly confirmed modules settle once, with no bounce or long cascade; moving an existing module never replays its entrance. Keep customer motion as it is. | Preserves spatial feedback while letting repeated edits feel immediate. | `src/scene/DesignStudio.tsx`, `src/scene/HouseScene.tsx` | M |
| **A restrained typing state beside reo.** While the existing ask request is pending, show a tiny dot indicator beside the vest avatar and a polite “Preparing an answer…” status. Replace it with the response or error, without shifting the header. | Disabled chips currently provide little explanation of what is happening; this confirms the question was received. | `src/Installer.tsx` (`AskReo`), `src/installer.css` | S |
| **A truthful, calm answer step line.** Use the existing request lifecycle for “Question sent” → “Preparing answer” → “Answer ready”; retain the returned run timeline below the answer. No invented tool progress or simulated stages while awaiting `run_id`. | Makes a longer wait understandable without promising work the UI cannot observe. | `src/Installer.tsx` (`AskReo`), `src/installer.css` | S |
| **Link selection to the hardware row.** When a device is selected in the scene/palette, give its matching hardware row a subtle border and clear focus style; Escape clears both. | Connects the visual object to its size control immediately, especially when several devices look similar. | `src/scene/DesignStudio.tsx`, `src/installer.css` | S |
| **Keep the last update result legible.** Reserve a single line for the studio's existing dirty/pending/success state and briefly retain a success acknowledgement after the response. An error must remain an error, never show “up to date” after a failed save. | Reduces status flicker during quick edits and makes persistence trustworthy. | `src/scene/DesignStudio.tsx`, `src/Installer.tsx` (pass successful/failed outcome), `src/installer.css` | M |
| **Contextual studio hint.** Reuse the existing HUD, showing a short hint for the current interaction: selected device, module drag, or idle. Use a lightly frosted background and enough contrast; keep the fuller instructions available. | The current long instruction line competes with the scene. A shorter, relevant hint is faster to scan and easier on a phone. | `src/scene/DesignStudio.tsx`, `src/installer.css` | S |

All options reuse existing state and calls: no new backend calls, no UI-derived design/price/saving values, and no layout redesign. Any displayed number must be copied from the engine response via reo. Motion should use the existing spring easing where suitable, remain interruptible, and become static feedback under `prefers-reduced-motion`. Keep customer branding white-label.
